# 查询基架设计

## 1. 目标

统一查询模型、分页排序、过滤表达与结果封装，避免查询接口碎片化。

## 2. 查询基架组成（固定）

- QueryGateway：查询入口
- QuerySpec：过滤与排序表达
- QueryHandler：具体查询实现
- QueryResult：统一结果模型

## 3. 查询契约

每个查询必须定义：
- queryCode
- 入参 DTO
- 排序白名单
- 分页策略
- 输出 DTO

## 4. 分页与排序

- page 从 1 开始
- pageSize 默认 20，最大 200
- sort 仅允许白名单字段

## 5. 过滤规范

- 必须支持精确匹配与区间查询
- 模糊查询必须有字段白名单
- 任意动态 SQL 条件必须参数化，禁止拼接注入

## 6. 查询性能

- 列表查询必须限制最大返回条数
- 大表查询必须使用索引字段过滤
- 复杂报表查询必须异步化为后台任务

## 7. 查询安全

- 查询侧必须接入数据权限过滤
- 非授权字段禁止返回
- 敏感字段默认脱敏

## 8. 可观测性

每个查询必须记录：
- queryCode
- durationMs
- resultCount
- traceId

## 9. 可执行验收

- QueryGateway 路由到对应 QueryHandler 成功
- 分页排序规则符合白名单约束
- 查询接口通过 SQL 注入回归测试
- 慢查询可被日志与指标识别


## 10. 标量输入技术边界

QuerySpec对上下界分别校验，不把不支持的值交给JDBC或静默舍入。BigDecimal按非科学计数表示计算整数与小数位数，包含必要的前导整数零，总位数最多512；计算使用long及precision/scale，不为检查而展开字符串。此资源限制独立于业务数量、价格和金额的更严格存储约束。

当前项目日期输入遵循[MariaDB DATE范围](https://mariadb.com/docs/server/reference/data-types/date-and-time-data-types/date)，仅1000至9999年；Instant按UTC对齐[DATETIME(6)](https://mariadb.com/docs/server/reference/data-types/date-and-time-data-types/datetime)，范围为1000-01-01T00:00:00Z至9999-12-31T23:59:59.999999Z，精度最多微秒。超界或纳秒输入直接拒绝，避免参数被数据库截断后改变精确或区间条件。
