# ADR-006：独立网关进程

## 状态
已接受（用户于2026-10-25确认独立网关进程，Starter继续承载ERP；只做本地开发与联调，不部署）。

## 背景
现有模块骨架由Starter聚合Gateway，尚无网关实现；网关规范要求统一入口及与项目外负载均衡分工，需要确定进程边界。ERP仍为多模块DDD单体，不拆分业务服务。

## 决策
stratum-gateway作为独立Spring Cloud Gateway应用运行，只依赖Common；Starter聚合ERP业务模块并移除对Gateway的运行时依赖。网关使用官方Server WebFlux/Netty入口，ERP继续使用既有MVC运行时；依赖版本统一在根工程管理，接入前核对与Boot 4/JDK 25的兼容性、许可和实际构建。

Gateway负责固定上游路由、Header灰度、限流、请求防护、追踪透传及入口观测；不访问业务数据库，不处理业务授权。Access、API权限与仓库范围继续由ERP校验。网关不在项目内选择负载均衡节点；上游地址指向单个App或项目外负载均衡地址。

## 权衡与影响
独立进程隔离入口资源和WebFlux/MVC运行时，需要分别启动和配置上游，增加一个本地进程。保留同进程MVC可减少启动单元，但入口与业务共享运行时；用户已选择独立方式。此选择不改变业务聚合、事务、QueryGateway、JWT或数据范围语义。

旧文档的“Spring Boot Gateway”按官方产品名称统一为Spring Cloud Gateway。官方[网关说明](https://docs.spring.io/spring-cloud-gateway/reference/)支持独立或嵌入式运行；[Server WebFlux入口](https://docs.spring.io/spring-cloud-gateway/reference/spring-cloud-gateway-server-webflux/starter.html)要求Netty运行时。

先更新架构与SDD规范并审查，再逐节点实施。D04.1只验证本地进程、路由和安全策略；D04.2、Compose、项目外负载均衡及多副本部署验收仍暂缓。规范变更不代表网关已经实现，不计为开发节点完成。

## 关联规范
SPEC-001、SPEC-002、SPEC-010、SPEC-012；对应D04.1及后续F02。冻结技术基线不变，Domain仍无框架依赖。
